LCM / LOSSLESS CONTEXT MANAGEMENT

小上下文，不等于丢历史Bounded context does not mean lost history

LCM 论文提出确定性的分层摘要 DAG：活动提示只携带近期原文和摘要节点，而每个摘要保留通向原始消息的指针。SuperLcm 把这一思路接到 DSH 的只追加会话日志上。

The LCM paper proposes a deterministic hierarchical summary DAG: the active prompt carries recent raw turns and summary nodes, while every summary retains pointers to its original messages. SuperLcm maps that idea onto DSH's append-only session log.

▤

不可变原文Immutable source

DSH Session Event Log 是唯一原文真源。SQLite 不复制整份 transcript。

The DSH session event log remains the only raw source of truth. SQLite does not duplicate the transcript.

⌘

分层摘要 DAGHierarchical DAG

较老批次形成 D0 摘要；需要时可继续合并成更高层节点，同时保留来源关系。

Older batches become D0 summaries and may later condense into higher levels while preserving provenance.

⌕

按需精确召回Exact recall on demand

Agent 可以搜索、查看、逐页展开摘要，最终回到确切的 DSH 事件序号。

The agent can search, inspect, and page through summaries until it reaches exact DSH event sequences.

TWO-PHASE / NON-BLOCKING

昂贵的摘要生成，移出用户等待路径Move expensive summarization off the user's wait path

传统同步压缩在请求临界点才开始摘要，用户必须等摘要完成。SuperLcm 提前选择安全区间并在独立 Worker 中生成摘要；对话继续进行，准备好的结果只在稳定性检查通过后原子提交。

Synchronous compaction starts summarizing at the pressure point and makes the user wait. SuperLcm stages a safe range earlier and summarizes it in a detached worker; the conversation continues, and the result is committed atomically only after stability checks pass.

  1. 1

    固定安全选区Stage a safe range

    保护最新消息和 token 下限，绝不拆开工具调用对。

    Protect the fresh tail and token floor without splitting tool-call pairs.

  2. 2

    后台独立摘要Summarize off-thread

    明确指定 provider/model，独立 AbortController，不借用当前 Agent。

    Use an explicit provider/model and independent abort controller—never the active agent.

  3. 3

    继续接收新消息Keep accepting turns

    尾部可以增长；摘要任务不会被 await 在当前回复里。

    The tail may grow; the active reply never awaits the summarization job.

  4. 4

    校验后原子提交Validate, then commit

    选区变化就丢弃重做；稳定时写入完整 DSH 压缩事务。

    Discard stale work; otherwise write one complete DSH compaction transaction.

WHY A SMALLER ACTIVE CONTEXT?

让 Agent 把注意力留给当前任务Keep the agent focused on the work at hand

01

减少等待Less waiting

摘要生成离开当前回复的阻塞路径。压力到来时，通常已有 ready 结果可提交。

Summary generation leaves the blocking reply path. A ready result is often available when pressure arrives.

02

保持较小上下文Bounded active context

模型少读无关旧内容，获得更多输出余量，也降低长上下文中的注意力稀释风险。

The model reads less stale material, gains output headroom, and faces less long-context distraction.

03

稳定缓存前缀Stable cache prefix

system 与已提交 checkpoint 冻结不改；后续只压缩其后的原文，尽量复用 Prompt Cache。

The system message and committed checkpoints stay byte-stable; later folds touch only newer raw history, maximizing prompt-cache reuse.

04

更低 token 与缓存成本Lower token and cache cost

更短的活动请求减少每轮输入 token；稳定前缀减少重复 cache write。实际价格取决于模型提供方。

Shorter active requests reduce input tokens, while a stable prefix avoids repeated cache writes. Exact savings depend on the provider.

PREFIX-STABLE CACHE DESIGN

不猜缓存多久，只保证前缀不乱变Do not guess cache TTL—keep the prefix stable

SuperLcm 不依赖“缓存几分钟后变冷”的猜测。提交后的 system 和 checkpoint 形成冻结前缀；新的压缩只处理后面的 raw history。只有硬压力且后段已经无法释放足够空间时，才合并旧 checkpoint。

SuperLcm does not guess when a cache becomes cold. The system message and committed checkpoints form a frozen prefix; new compaction only touches later raw history. Old checkpoints merge only as a hard-pressure fallback.
